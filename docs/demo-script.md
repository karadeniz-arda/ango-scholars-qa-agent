# 5–10 minute evidence-based demo

## Before starting

Use saved local artifacts only; do not display credentials, cookies, tokens, or environment files. Do not rerun planner or browser work for this walkthrough. State that Fresh31 is a frozen reproducibility checkpoint and Final-13 is a historical compatibility corpus.

## Script

### 1. Authority model — 1 minute

Show [architecture.md](architecture.md) and say: **`EXECUTED != PROVED`**. A PASS needs source authority, an exact typed contract, accepted runtime context, fresh deterministic evidence, and a clean audit. Model decisions and visual review are diagnostic only.

### 2. AS-1058 source-bound proof — 2 minutes

Open the Fresh31 AS-1058 saved log/report. Show the source-bound literal checks (for example `Listening`, `Speaking`, `Writing`, and `Reading`) and their stable source/check identities. Explain: source authorizes the members; the compiler binds checks; fresh browser evidence discharges only the matching requirement/case.

Claim only current real-UI evidence for supported literal/member semantics.

### 3. AS-1311 false-PASS prevention — 2 minutes

Open the AS-1311 Fresh31 result. The model said `GOAL_ALREADY_SATISFIED`, but the source-authorized `Download as PDF` deterministic check failed. Explain why the result is `FAIL`, not PASS, and why this is a product/requirement observation rather than an automatic agent regression.

### 4. Honest blocking — 1 minute

Show a fixture/entity-blocked case. A usable session or route cannot create compatible required test data. The system returns `BLOCKED` instead of fabricating data. General unattended fixture provisioning/cleanup is not production-ready.

### 5. Fresh31 reproducibility — 1–2 minutes

Show the A/B/C totals: each is PASS 2, FAIL 1, BLOCKED 25, MANUAL_REQUIRED 9, ERROR 0. State `STABLE_CASE_AND_TECHNICAL`: zero A–B status delta, zero B–C status/technical delta, and zero PASS asymmetry.

### 6. Close — 30 seconds

The success is preserving the requirement → execution → proof → verdict boundary and surfacing the first blocker honestly, not maximizing click count or PASS count.

## What not to claim

Do not claim universal unattended Jira coverage, universal fixture cleanup, screenshot/video proof, model-positive PASS, historical Final-13 PASS parity, product certification, or ML-benchmark generalization. Do not present partial route, structural-control, query/filter, or state-transition evidence as universal capability coverage.

## Questions to expect

**Why so many BLOCKED/MANUAL_REQUIRED results?** Missing prerequisites or proof authority are reported rather than guessed.

**Why not trust a screenshot?** It can be incomplete or disconnected from the exact source requirement; it is diagnostic, not proof authority.

**Why retain Final-13?** It distinguishes compatibility/environment drift from actual agent regressions, but does not define today's PASS floor.

**What is next?** Typed fixture authority and isolated cleanup proof first; then only source-backed proof primitives with bounded generic grounding.
